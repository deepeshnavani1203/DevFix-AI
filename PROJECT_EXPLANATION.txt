1. PROJECT KA 30-SECOND ELEVATOR PITCH (KISI KO QUICKLY BATANE KE LIYE)
================================================================================
"DevFix AI ek autonomous multi-agent AI debugging system hai.
Ye Python code aur error tracebacks ko analyze karta hai, root cause dhundhta hai, 
Qdrant vector database se RAG ke through verified solutions retrieve karta hai, 
Groq LLM se accurate fix generate karta hai, aur MCP (Model Context Protocol) 
ke through isolated sandbox environment me tests run karke fix ko validate karta hai. 
Frontend React + Vite me hai aur Backend FastAPI + uv package manager me hai."

================================================================================
2. MULTI-AGENT WORKFLOW (LANGGRAPH) — KAUNSE AGENTS HAIN AUR KAISE KAAM KARTE HAIN?
================================================================================
Humne LangGraph (StateGraph) use kiya hai. Ye ek directed graph workflow banata 
hai jisme saare agents ek shared memory/state (DebugState) share karte hain.

Graph Flow:
START ──> [ Agent 1: Error Analysis ]
                     │
                     ▼
          [ Agent 2: RAG Debugging ]
                     │
                     ▼
          [ Agent 3: Fix Validation ] ──> END

• AGENT 1: Error Analysis Agent (analyzer.py)
  - Kaam: User ka code aur traceback inspect karna.
  - Tools used: MCP analyze_code aur MCP read_error_log.
  - Output: Error type (e.g. ZeroDivisionError), error line, root cause hypotheses.

• AGENT 2: RAG Debugging Agent (rag_agent.py)
  - Kaam: Qdrant vector database me similar past bugs aur verified fixes search karna.
  - Tools used: MCP search_debug_knowledge.
  - Output: Top 3 matching verified examples (score, title, verified fix code).

• AGENT 3: Fix Validation Agent (validator.py)
  - Kaam: Groq LLM se final solution + test assertion suite generate karwana, 
    aur phir use safe sandbox me execute karke test pass/fail check karna.
  - Tools used: MCP run_tests.
  - Output: Corrected code, step-by-step explanation, test pass/fail status, duration_ms.

KYU LANGGRAPH USE KIYA?
Normal simple linear scripts me agent state tracking, debugging, aur rollback 
mushkil hota hai. LangGraph production-ready orchestration deta hai jisme 
clear state transitions aur modularity rehti hai.

3. MCP (MODEL CONTEXT PROTOCOL) — KYA, KYU, AUR KAISE USE KIYA?
================================================================================

1) MCP KYA HAI?
   - MCP (Model Context Protocol) Anthropic ka open standard protocol hai jisse 
     AI models aur external tools/resources ke beech me clean communication hoti hai.
   - Humne official Python SDK (`mcp 2.x`) use kiya hai.

2) MCP KYU USE KIYA? (WHY MCP INSTEAD OF NORMAL PYTHON FUNCTIONS?)
   - Standardization: AI agents ko direct randomly code execute karne ya custom 
     hacks ki jagah ek standard tool interface milta hai.
   - Safety & Guardrails: MCP tools ke andar boundaries hoti hain (e.g. unsafe 
     calls block karna, timeouts enforce karna).
   - Reusability: Koi bhi Claude Code, Cursor, ya external MCP client directly 
     tumhare backend ke MCP tools ko connect karke use kar sakta hai.

3) MCP KAISE IMPLEMENT KIYA?
   Humne Client-Server architecture implement kiya:
   - Server: `backend/mcp_server/server.py` -> `MCPServer("devfix-mcp-server")`
   - Client: `backend/mcp_server/client.py` -> `DevFixMCPClient()` jisko hamare 
     LangGraph agents direct call karte hain.

4) MCP ME KAUNSE 4 TOOLS HAIN?
   Tool 1: `analyze_code(code: str)`
     - Python AST (`ast.parse`) se syntax check karta hai.
     - Functions, classes, imports list karta hai.
     - Dangerous calls detect karta hai (`eval`, `exec`, `os.system`, `subprocess`) 
       aur security warning deta hai.
     - Anti-patterns spot karta hai (e.g. mutable default argument `def fn(x=[])`).

   Tool 2: `read_error_log(error_log: str)`
     - Raw terminal traceback ko parse karta hai.
     - Exception type, offending file, line number aur call stack nikalta hai.

   Tool 3: `search_debug_knowledge(query: str, limit: int)`
     - Agent ko Qdrant RAG se connect karta hai aur relevant past cases laata hai.

   Tool 4: `run_tests(solution_code: str, test_code: str, timeout_seconds: int)`
     - VERY IMPORTANT: Ye code ko directly main server process me run nahi karta!
     - Ye isolated temporary file banata hai aur clean subprocess me `python -I` 
       (isolated mode) ke sath run karta hai with strict 3-second timeout.
     - Infinite loops ya freeze hona block ho jata hai.
     - Assertions pass/fail, execution time (ms), stdout/stderr return karta hai.

4. RAG (RETRIEVAL-AUGMENTED GENERATION) — KYA, KYU, AUR KAISE USE KIYA?
================================================================================

1) RAG KYA HAI?
   - RAG ka matlab hai: LLM ko bina retraining ke external knowledge base se 
     accurate, verified context provide karna taaki wo hallucinate na kare.

2) RAG KYU USE KIYA?
   - LLMs generic Python jante hain, lekin real-world edge cases (e.g. mutable 
     default arguments, shallow copy trap, IEEE float 0.1+0.2!=0.3) par galat 
     suggestions de dete hain.
   - RAG ke through hum AI ko verified debugging cases aur proven fixes dikhate hain, 
     jisse AI 10x zyada accurate code generate karta hai.

3) RAG ME TECHNIQUE AUR WORKFLOW KYA HAI?
   Step A: Knowledge Dataset (`backend/data/knowledge/python_errors.json`)
     - 35 high-quality verified real-world Python bug cases.
     - Har case me: error_type, root_cause, buggy_code, corrected_code, test_code, 
       category, tags hote hain.

   Step B: Chunking & Metadata (`backend/rag/chunking.py`)
     - Text representation prepare hoti hai jisme Error Type, Cause, Buggy Example, 
       Corrected Code aur Tags structured hote hain.

   Step C: Local Embeddings (`backend/rag/embeddings.py`)
     - Model: `sentence-transformers/all-MiniLM-L6-v2`
     - Dense Vectors: 384 dimensions.
     - KYU YE USE KIYA? Ye 100% free hai, local CPU par super-fast chalta hai, 
       aur kisi paid OpenAI embedding API key ki zaroorat nahi padti.

   Step D: Vector Database (`backend/services/qdrant_service.py`)
     - Vector DB: **Qdrant**
     - Metric: Cosine Distance.
     - Storage Mode: Local persistent disk storage (`./backend/qdrant_storage`).
       (Matlab Docker ya Qdrant Cloud ke bina bhi tumhare laptop par permanently save rehta hai!)

   Step E: Semantic Similarity Search (`backend/rag/retriever.py`)
     - Jab user code aur error bhejta hai, RAG Retriever us query ko vector me 
       convert karta hai aur Qdrant se top-3 matching records fetch karta hai.

   Step F: Privacy & Sensitive Data Scrubbing
     - Agar user apna fix knowledge base me save karna chahta hai (Opt-in), 
       hum regex privacy sanitizer chalate hain jo API keys (`sk-...`, `gsk_...`), 
       passwords aur tokens ko automatically `[REDACTED_SECRET]` se replace kar deta hai.
     - History aur Reusable Knowledge alag-alag stores me rehte hain.

5. FRONTEND & BACKEND CONNECTION (END-TO-END FLOW)
================================================================================

1) Frontend:
   - React 19 + Vite (Running on http://localhost:5173)
   - Dark Developer Theme (Inter & JetBrains Mono typography, Glassmorphism, Neon glow).
   - 3 Tabs:
     a) Debug Studio: Code editor, traceback input, 1-click sample presets, 
        live multi-agent visual stepper, MCP badges, verified fix diff, 
        sandbox test outcome, opt-in "Save to Knowledge Base" button.
     b) Knowledge Base Tab: Qdrant ke 35+ verified cases live search aur view.
     c) History Tab: Past sessions review aur studio me reload.

2) Backend:
   - FastAPI + Uvicorn (Running on http://localhost:8000)
   - Package manager: `uv` (modern, ultra-fast Python package manager)
   - Endpoints:
     - GET  /api/health         -> Health check of Groq, Qdrant, MCP, LangGraph
     - POST /api/debug          -> Main multi-agent debugging workflow
     - POST /api/debug/upload   -> Python (.py) file upload
     - GET  /api/knowledge      -> List all records in Qdrant
     - POST /api/knowledge/save -> Scrub & save user-approved verified fix
     - GET  /api/history        -> Retrieve past debug sessions
     - DELETE /api/history      -> Clear history

3) Full Request Cycle (Step-by-step):
   User clicks "Analyze & Fix" on React Frontend
   ──> POST request to FastAPI `/api/debug`
   ──> FastAPI invokes LangGraph StateGraph
   ──> Agent 1 calls MCP `analyze_code` (AST) & `read_error_log`
   ──> Agent 2 embeds query & calls MCP `search_debug_knowledge` (Qdrant)
   ──> Agent 3 sends context to Groq LLM to synthesize fix
   ──> Agent 3 calls MCP `run_tests` in isolated Python subprocess
   ──> Output aggregated in `DebugState`
   ──> JSON response sent back to React UI
   ──> UI renders badges, diff code, test pass/fail, and RAG citations!

6. COMMON INTERVIEW QUESTIONS & CRISP ANSWERS
================================================================================

Q1: "Project me LangGraph kyu use kiya, simple chain ya loop kyu nahi?"
Ans: "LangGraph ek cyclic multi-agent graph orchestration provide karta hai jisme 
     har agent ka input/output ek strongly-typed state (`DebugState`) me persist 
     hota hai. Isse Error Analysis, RAG, aur Sandbox Validation ke beech modular 
     boundaries ban jaati hain aur debugging bahut easy ho jati hai."

Q2: "MCP kyu use kiya normal Python helper functions ki jagah?"
Ans: "MCP (Model Context Protocol) AI tooling ka modern industry standard hai. 
     Isse tools standardize hote hain, static AST validation aur sandboxed execution 
     ki security boundaries enforce hoti hain, aur koi bhi external AI agent 
     (e.g. Claude Code ya Cursor) hamare MCP tools ko plug-and-play use kar sakta hai."

Q3: "Qdrant ko local mode me kaise use kiya bina Docker ke?"
Ans: "qdrant-client me embedded on-disk mode support hota hai (`QdrantClient(path='./qdrant_storage')`). 
     Humne ye fallback banaya hai taaki bina Docker install kiye bhi vector database 
     locally laptop par persist ho sake, jabki Docker URL (`http://localhost:6333`) 
     bhi fully supported hai."

Q4: "Code execution safe kaise rakha hai?"
Ans: "Do levels of protection hain:
     1) Pre-execution AST check: MCP `analyze_code` dangerous functions (`eval`, `exec`, 
        `os.system`) ko pehle hi block kar deta hai.
     2) Sandboxed subprocess: MCP `run_tests` code ko `python -I` (isolated environment) 
        me 3-second strict timeout ke sath execute karta hai taaki infinite loop ya 
        server freeze na ho sake."

Q5: "Privacy kaise handle ki hai?"
Ans: "Har debugging session sirf in-memory history me jata hai. Vector DB me user 
     code tabhi jata hai jab user explicitly opt-in kare. Aur save karne se pehle 
     hum regex privacy scrubber se API keys, passwords aur tokens redact karte hain."
